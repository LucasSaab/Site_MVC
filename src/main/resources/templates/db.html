2. Limitações da abordagem

⚠️ Observação Técnica: volatilidade

Os dados residem no heap da JVM. Ao reiniciar a aplicação, a coleção retorna ao estado definido no construtor do Controller, pois não há persistência em disco.

🔍 O que ocorre no Servidor?

Como o Controller é um bean singleton, a mesma instância da lista é compartilhada por todas as requisições. A coleção utilizada não é thread-safe, o que é aceitável para demonstração com acesso apenas de leitura, mas inadequado quando há escrita concorrente.

💡 Conceito Teórico: persistência e camadas de acesso a dados

Em sistemas de produção, o estado é delegado a um mecanismo de persistência, em geral com camadas dedicadas de acesso a dados. Este projeto as omite deliberadamente para manter o foco na colaboração entre Model, View e Controller.
