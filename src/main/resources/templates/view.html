Camada View: Server-Side Rendering com Thymeleaf

A View transforma os atributos recebidos do Controller em um documento HTML, sem buscar, alterar ou decidir sobre os dados.

  • View
  • Server-Side Rendering
  • Data Binding

1. Fundamentação teórica

No Server-Side Rendering (SSR), o documento HTML é composto no servidor a cada requisição. O cliente recebe marcação completa e a exibe diretamente, o que simplifica a camada de apresentação e favorece a indexação e o tempo até o primeiro conteúdo visível.

Conceito Teórico: Data Binding

Na exibição, os dados fluem do Model para o template: o Thymeleaf avalia expressões ${...} contra os atributos da requisição e incorpora os resultados ao HTML. Em formulários, th:object e th:field estabelecem o binding nos dois sentidos: ao renderizar, os valores do objeto preenchem os campos; ao submeter, o Spring converte os parâmetros da requisição e preenche novamente o objeto (@ModelAttribute).

3. Do template ao documento final

O arquivo-fonte contém atributos th:* e conteúdo de exemplo; o navegador recebe apenas HTML padrão.

O que ocorre no Servidor?

O ThymeleafViewResolver localiza o template pelo nome lógico retornado pelo Controller. O motor analisa o arquivo, executa os processadores dos atributos th:* e serializa o resultado como HTML, que é enviado na resposta.

Conceito Teórico: Natural Templates

O template permanece um HTML válido quando aberto diretamente no navegador, exibindo o conteúdo de exemplo. Isso permite que o trabalho de design e o de programação ocorram sobre o mesmo artefato.

Observação Técnica: escape de saída

O atributo th:text escapa caracteres especiais, o que mitiga ataques de Cross-Site Scripting (XSS). O atributo th:utext não realiza esse escape e deve ser evitado com dados de origem não confiável.

5. Formulários: th:object, th:field e proteção CSRF

Aprofundamento

Formulários exigem uma associação explícita entre os campos HTML e um objeto do Model. O Thymeleaf a estabelece com th:object, que define o objeto-alvo, e com th:field, que liga cada campo a um atributo desse objeto por meio de expressões de seleção *{...}.

ElementoFunção
th:objectDefine o objeto do Model ao qual o formulário está vinculado, enviado pelo Controller, por exemplo com model.addAttribute("projeto", new Projeto()).
th:fieldGera id, name e value do campo a partir de um atributo do objeto e marca a opção selecionada em um <select>.
th:actionResolve a URL de envio relativa ao contexto da aplicação e, com Spring Security, insere o token CSRF.
@ModelAttributeNo Controller, converte os parâmetros da requisição e preenche uma instância do Model (Data Binding no sentido View → Model).

5.1 Proteção contra CSRF

O Cross-Site Request Forgery (CSRF) é um ataque em que um site malicioso induz o navegador autenticado do usuário a enviar uma requisição que altera estado, como um POST de exclusão. A defesa usual é o token sincronizador: o servidor emite um valor imprevisível (_csrf), incluído como campo oculto no formulário e verificado a cada requisição de escrita. Com o Spring Security habilitado, o Thymeleaf insere esse campo automaticamente nos formulários que usam th:action com método POST.

Observação Técnica

O projeto didático não utiliza Spring Security e, portanto, não possui proteção CSRF. Em produção, ela é necessária em toda operação que altere estado (POST, PUT e DELETE).

6. Questões de fixação

Por que razões o Thymeleaf é considerado uma tecnologia de Natural Templates?

Porque os atributos th:* são ignorados pelo navegador: o arquivo continua sendo HTML válido e exibe o conteúdo de exemplo quando aberto diretamente. Quando processado pelo servidor, esses atributos substituem o conteúdo de exemplo pelos dados reais, o que permite que design e programação trabalhem sobre o mesmo artefato.

O que é CSRF e como o Thymeleaf contribui para a proteção?

CSRF é um ataque em que um site malicioso induz o navegador do usuário a enviar uma requisição de escrita a outra aplicação. A defesa é o token sincronizador (_csrf). Com o Spring Security ativo, o Thymeleaf insere automaticamente o campo oculto com o token nos formulários POST que usam th:action.
